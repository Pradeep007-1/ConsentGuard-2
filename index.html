Policy Enforcement Point (PEP) Gatekeeper Algorithm — Pseudocode View PS-002 Deliverable #3
The downstream boundary operates as a strict Policy Enforcement Point (PEP). Every request must present active valid consent cryptographically anchored to the active privacy notice SHA-256 digest: 
FUNCTION EnforceDataAccess(userId, requestedPurpose):
    // Step 1: Validate purpose against inventory
    IF requestedPurpose NOT IN { "Analytics", "Marketing", "Service Improvement" }:
        RETURN HTTP 400 ("Invalid Purpose")

    // Step 2: Query active consent ledger
    consentRecord = DB.Query("SELECT granted, notice_version FROM consents 
                             WHERE user_id = ? AND purpose = ?", userId, requestedPurpose)

    // Step 3: Fetch active privacy notice version & SHA-256 digest
    activeVersion, activeHash = System.GetNoticeMetadata()

    // Step 4: Strict Policy Boundary Verification
    IF consentRecord IS NULL:
        LogAudit(userId, requestedPurpose, "data_access_denied", "Explicit opt-in required")
        RETURN HTTP 403 ("Access Denied: No consent on record")

    IF consentRecord.granted != 1:
        LogAudit(userId, requestedPurpose, "data_access_denied", "Consent revoked/withdrawn")
        RETURN HTTP 403 ("Access Denied: Consent withdrawn")

    IF consentRecord.notice_version != activeVersion:
        LogAudit(userId, requestedPurpose, "data_access_denied", "Notice version obsolete")
        RETURN HTTP 403 ("Access Denied: Privacy notice changed; fresh consent required")

    // Step 5: Authorization granted
    LogAudit(userId, requestedPurpose, "data_access_allowed", "PEP verified active consent; SHA256=" + activeHash)
    RETURN HTTP 200 (MOCK_DATA[requestedPurpose])
